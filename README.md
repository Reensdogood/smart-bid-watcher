# Smart Bid Watcher

나라장터의 입찰공고·발주계획·사전규격을 주기적으로 조회하고 새 항목을 ntfy로 알려주는 Windows 트레이 앱입니다. PySide6 네이티브 앱이며 웹 서버나 localhost를 실행하지 않습니다.

## 주요 기능

- 입찰공고, 발주계획, 사전규격을 각각 선택해 조회
- 여러 검색어와 AND/OR 조건, 제외 단어
- 5/10/20/30분 확인 주기
- 운영 시간과 운영 요일 설정(기본 평일 09:00–19:00)
- 대한민국 공휴일·대체공휴일 자동 제외 옵션
- 공고별 고유번호로 중복 알림 방지
- 첫 확인 시 최근 7일 자료를 기준선으로 저장
- ntfy 앱 푸시 알림
- SQLite 이력 저장, Windows 시작프로그램, 시스템 트레이
- PyInstaller 단일 EXE 빌드

## 처음 설정하기

### 1. 공공데이터포털 인증키

공공데이터포털에서 사용할 조회 대상의 활용신청을 각각 완료합니다.

- [나라장터 입찰공고정보서비스](https://www.data.go.kr/data/15129394/openapi.do)
- [나라장터 발주계획현황서비스](https://www.data.go.kr/data/15129462/openapi.do)
- [나라장터 사전규격정보서비스](https://www.data.go.kr/data/15129437/openapi.do)

공공데이터포털의 **일반 인증키** 하나를 앱의 `연결 설정 → 나라장터 OpenAPI 인증키`에 입력합니다. 이 키를 입찰공고·발주계획·사전규격 조회에 공통으로 사용합니다. 선택한 서비스의 활용신청이 빠졌거나 키가 만료되면 해당 조회는 실패하며 앱이 트레이와 상태 영역에 오류를 표시합니다.

### 2. ntfy 알림

1. 휴대폰에 ntfy 앱을 설치합니다.
2. 앱의 `연결 설정 → 구독 토픽`에 표시된 토픽을 휴대폰 ntfy 앱에서도 동일하게 구독합니다.
3. `테스트 발송`으로 수신을 확인합니다.

공용 `ntfy.sh`에서는 토픽 이름을 아는 사람이 메시지를 볼 수 있으므로 자동 생성된 추측하기 어려운 토픽을 그대로 쓰는 것을 권장합니다.

## 사용 흐름

1. 검색어를 한 줄에 하나씩 입력합니다.
2. 입찰공고·발주계획·사전규격 중 조회 대상을 선택합니다.
3. OR/AND, 제외 단어, 확인 주기와 운영 시간·요일을 설정합니다.
4. `지금 확인`으로 먼저 결과를 확인합니다.
5. `모니터링 시작`을 누르면 창이 자동으로 트레이로 숨겨지고 주기 조회를 계속합니다.

정상적으로 시작되면 Windows 알림에 확인 주기가 표시됩니다. 트레이 아이콘에 마우스를 올리면 실행 상태와 마지막 확인 시간을 볼 수 있고, 아이콘을 더블클릭하면 창을 다시 열 수 있습니다.

기본 운영 스케줄은 월–금 09:00–19:00이며 토·일요일과 대한민국 공휴일·대체공휴일에는 API를 호출하지 않습니다. 운영 시간 밖에는 트레이 상태에 다음 시작 시각을 표시하며 대기합니다. 요일, 시작·종료 시간, 공휴일 제외 여부는 모니터링 탭에서 변경할 수 있습니다. `지금 확인`은 사용자가 직접 요청하는 수동 확인이므로 스케줄과 관계없이 한 번 실행됩니다.

앱을 직접 실행하거나 `Windows 시작 시 설정 창 열기`로 실행한 경우에도 먼저 설정 창이 표시됩니다. 앱이 임의로 모니터링을 시작하거나 트레이로 숨지 않으며, 검색어·조회 대상·API 키를 확인하고 사용자가 `모니터링 시작`을 눌러야만 작동합니다. 인증키 입력란의 점 표시는 화면 마스킹일 뿐이며 `표시` 버튼으로 실제 입력값 존재 여부를 확인할 수 있습니다.

첫 확인 또는 검색 조건 변경 직후에는 최근 7일의 일치 항목을 목록에 저장하지만 ntfy 알림은 보내지 않습니다. 이후 조회부터 처음 나타난 고유번호만 알립니다. 상태 영역의 `전체 N건`은 API 응답 수, `검색어 일치 N건`은 실제 저장 대상 수입니다.

설정은 `%LOCALAPPDATA%\SmartBidWatcher\config.json`, 공고 이력은 같은 폴더의 `bid.db`에 저장됩니다.

## 소스에서 실행

```powershell
.\run.ps1
```

## 단일 EXE 만들기

```powershell
.\build.ps1
```

완료 파일은 `dist\Smart Bid Watcher.exe`입니다. 첫 실행 시 Windows SmartScreen 경고가 나타날 수 있으며 외부 배포 시 코드 서명을 권장합니다.

## 프로젝트 구조

```text
smart_bid_watcher/
├─ config.py          설정 파일 관리
├─ matching.py        AND/OR 및 제외어 판정
├─ monitor.py         주기 실행, 기준선, 신규 판정
├─ notifier.py        ntfy 발송
├─ schedule.py        운영 시간·요일·대한민국 공휴일 판정
├─ storage.py         SQLite 저장소
├─ startup.py         Windows 시작프로그램
├─ providers/
│  ├─ base.py         추가 조달 사이트용 인터페이스
│  ├─ g2b.py          입찰공고
│  ├─ order_plan.py   발주계획
│  └─ pre_spec.py     사전규격
└─ ui/                PySide6 네이티브 UI와 트레이
```

추가 조달 사이트는 `ProcurementProvider` 구현체를 만든 뒤 모니터의 공급자 목록에 등록하는 방식으로 확장할 수 있습니다.

## 문제 확인

- `API 키 필요`: 현재 선택한 조회 대상에 해당하는 일반 인증키가 저장되지 않았습니다.
- `SERVICE_ACCESS_DENIED_ERROR`: 선택한 OpenAPI의 활용신청 상태를 확인합니다.
- `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`: 인증키 값 또는 사용 기간을 확인합니다.
- `전체 N건 · 검색어 일치 0건`: API 조회는 성공했지만 제목/기관명에 검색어가 없거나 제외 단어에 걸렸습니다.
- 첫 확인에서 알림이 오지 않음: 정상입니다. 기존 항목은 기준선으로 목록에만 저장합니다.

PC가 켜져 있고 앱이 실행 중일 때만 주기 조회가 동작합니다. ntfy 전송 실패 항목은 `pending`으로 남겨 다음 확인 때 다시 보냅니다.
